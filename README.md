# Scenivo

面向小团队的内网资源管理平台，固定为资产库、场景库、看板库，不按项目隔离。资产是单个设备或物体；场景是在外部软件中组合好的完整 GLB；看板是 HTML 静态数据大屏模板。场景不会拆分为资产，也不会随单体资产更新自动变化。不包含审核、任务排期或在线场景编辑。

## 功能

- 统一团队账号与管理员、编辑者、查看者角色；资产、场景、看板各有独立的两级分类，可新增、改名、删除，删除分类仅将内容移至未分类。
- 资产库与场景库分开导入、预览和检索；多文件与文件夹批量上传，每项显示进度和错误，可重试失败项。
- 固定侧栏导航、分类筛选与标签搜索；列表只读取元数据与已有缩略图，不下载 GLB、看板源码包或运行 iframe。
- 卡片缩略图保持比例并裁切铺满预览区，完整内容在详情中查看。侧栏仅保留三个库，主内容区提供各库独立分类筛选；选中一级分类后展开子分类，管理入口位于筛选区。
- 多人修改使用单调递增修订号校验；过期提交明确报冲突，不自动覆盖。上传使用持久幂等回执，网络失败重试不会重复入库。
- 看板库支持 HTML、ZIP、文件夹、固定版本、PNG 截图、上下架、源码下载与显式隔离运行预览；只允许管理员管理看板。
- 原始 GLB 完整保留，新增版本不覆盖历史；可预览、下载任意历史版本并切换当前版本。
- 本地生成缩略图；旋转、缩放、平移、适配视角、网格、坐标轴、线框。
- GLB 自带动画的片段选择、播放/暂停、进度和速度控制。
- Three.js、Draco、Meshopt、KTX2 解码资源均由本机服务提供，无 CDN。
- 模型文件、截图、看板包和下载接口均检查登录状态及团队角色。
- 登录页、工作区右上角与设置统一使用太阳／月亮胶囊滑块切换浅色和深色，不再提供主题下拉框或单独图标按钮。首次访问采用系统当前配色，手动选择保存在当前浏览器并同步同源标签页；三维预览背景与网格同步变化，模型材质、相机和动画状态不重置。缩略图保持固定背景，不因个人主题重新生成。
- 侧栏底部“设置”提供通用偏好、数据与部署、关于与更新。默认打开库和默认排序保存到当前浏览器；具体资源直达链接不被偏好重定向。数据页从服务器读取真实数量、版本数和上传原始字节累计（不是磁盘占用），数据目录与运行环境仅管理员可见。
- 侧栏底部仅保留设置与当前账号；管理员从设置的通用页进入团队账号管理，不再展示内网资源库说明卡片。
- “检查更新”比较页面编译版本与当前服务器部署版本，不查询公网、不下载安装。版本不一致时提供手动刷新，并提醒未提交内容不会自动保存。更新记录维护于 src/release.ts，发布时同步 package.json 版本。
- 库页不显示可编辑/只读标记、装饰性英文标题和重复操作说明；设置与弹窗同样保持简洁。错误、冲突、进度、文件限制、版本信息及必要安全提醒保留，权限校验不变。

## 本机运行

需要 Node.js 20.19+（推荐 Node.js 22 LTS）、npm，浏览器推荐近期 Chrome / Edge，要求 WebGL 2 和 Promise.withResolvers。首次安装需要访问 npm；运行期无需访问公网。better-sqlite3 是原生模块，如没有可用预编译包，需要系统 C++ 编译环境。

```bash
npm ci
npm run build
npm start
```

打开 http://127.0.0.1:3187 。首次进入创建管理员，没有预置账号或默认密码。先完成初始化，再开放给团队，避免其他人抢先创建首位管理员。

创建账号时密码至少 6 位，不要求字符组合；输入框隐藏明文且不展示密码示例。原有较长密码仍然可用。短密码强度较低，请仅向可信内网开放并保留登录限流。

开发时两个终端分别运行：

```bash
npm run server
npm run dev
```

Vite 默认 http://127.0.0.1:5173 ，代理 `/api` 到 3187 端口。

## 内网部署

单服务 + SQLite + 本地磁盘。默认只监听本机。

Linux / macOS：

```bash
HOST=0.0.0.0 PORT=3187 DATA_DIR=/srv/model-library/data npm start
```

Windows PowerShell：

```powershell
$env:HOST = '0.0.0.0'
$env:PORT = '3187'
$env:DATA_DIR = 'D:\model-library-data'
npm start
```

团队访问 `http://服务器内网IP:3187`，按需配置防火墙。正式环境建议 HTTPS；HTTP 不加密账号和文件。使用 HTTPS 反向代理时设置 `TRUST_PROXY=1`，仅允许受信任的一层代理访问后端，后端端口不能直接暴露给不可信网络。GLB 上限为 512 MiB，代理建议 `client_max_body_size 520m`（预留 multipart 开销）、`client_body_timeout 900s`、`proxy_send_timeout 900s`、`proxy_read_timeout 900s`；应用的模型传输和解码超时为 15 分钟。登录使用 HttpOnly / SameSite Cookie，HTTPS 下自动启用 Secure。

普通内网 HTTP 地址支持上传：浏览器标识使用 crypto.getRandomValues 生成 UUID v4，不依赖仅限安全上下文的 crypto.randomUUID。仍建议生产启用 HTTPS；此兼容修复不为 HTTP 增加传输加密。

也可使用 Docker Compose（需先联网拉取镜像和构建）：

```bash
docker compose up -d --build
```

数据保存在命名卷 `model-data`，不要使用 `docker compose down -v`，除非确定要销毁全部数据。离线机器需要提前导入构建好的镜像；容器启动和模型预览不要求公网。

## 使用顺序

1. 首次创建管理员，在“团队账号”中创建编辑者或查看者。
2. 直接打开资产、场景或看板库，创建该库分类。
3. 资产和场景选择 GLB 入库；同名且不同上传请求仍创建独立条目，不按名称合并。
4. 更新同一内容时使用“上传新版本”，提交基于打开时的修订号；有冲突时先读取最新信息，由用户明确重新提交。
5. 历史版本可预览和下载，也可显式设为当前；切换当前版本也校验修订号。
6. 管理员上传看板 HTML/ZIP/完整文件夹，选择 HTML 入口。列表和详情默认只展示已有截图；点击“隔离运行预览”后才加载和执行模板。

所有已登录成员可浏览全库。编辑者可管理资产、场景及其分类；管理员额外管理账号、看板及上下架；查看者只读。降级账号会撤销其现有会话；最后一个管理员不可降级。当前不提供资源和账号永久删除，避免误删历史。

上传第一次提交后固定文件、元数据、基线修订号和请求标识；失败重试沿用同一标识。相同标识配不同内容会被拒绝。版本冲突后只有明确确认读取最新基线并重新提交才生成新的请求标识，不自动重新发布。幂等回执保存在数据库，服务重启后仍生效；不等同于对相同文件全局去重。

## 文件边界

- 单个 GLB 最大 512 MiB（界面简写 MB）；看板总上传仍为 100 MiB，PNG 仍为 2 MiB。只接受自包含的 GLB 2.0；外部贴图和缓冲区引用会被拒绝，请在建模软件中打包导出。
- 上传检查 GLB 头、块边界和关键结构，不等价于完整 Khronos glTF 校验；允许 BIN 含未引用尾部内容，但声明缓冲区不能超过 BIN，bufferView 不得越界。错误会提供声明值和实际值。损坏几何或不支持扩展仍可能在查看器中报错，原文件不会被转码修改。
- 支持常用 Draco、Meshopt、KTX2 资源解码，不能保证所有厂商扩展；上线前请用团队真实模型验证。
- 缩略图在浏览器生成，依赖可用 WebGL；上传按顺序生成，失败显示具体原因且不影响原文件入库。列表的“补建缩略图”只在主动操作后串行读取缺图模型，普通浏览不下载模型；详情加载成功时自动补存缺失缩略图，手动“保存当前视图为缩略图”直接截取现有渲染器，不重复下载或解码。
- 场景使用 GLB 的默认场景，保留原始变换，只移动查看相机以适配模型。大场景的流畅度受显卡、面数和贴图内存影响。
- 三类库是统一团队资源，不存在项目访问范围或资产依赖推导。
- 版本说明按 UTF-8 文本保存并原文显示。每版提供“修改说明”，修正旧说明会校验修订号并保留模型字节；不自动猜测乱码的原始含义。若导入脚本已将文字错误转码，应修复脚本输入并显式更正说明，不能通过更换字体恢复丢失字符。

## 看板模板与隔离

- 接受单个 UTF-8 HTML、ZIP、或带 HTML 入口的文件夹；保留原始 HTML/ZIP 字节，文件夹下载为保持路径和文件字节的 ZIP。
- 看板上传总量上限 100 MB，最多 2000 个文件，ZIP 展开总量上限 200 MB；服务端拒绝越界、重复/大小写冲突路径、文件与目录冲突、符号链接、加密 ZIP、损坏 CRC 和不完整文件。这些是安全上限，不是任意大包性能承诺。
- 原始源码仅存储，不执行 npm、Python 或服务器脚本。Vue/React 源码工程需先构建并选择 dist/build 中的 HTML；附属说明、脚本可保留作为下载附件。
- 模板列表没有截图时显示“暂无截图”；管理员上传 PNG 绑定到指定固定版本，新版本不会继承旧截图。截图由上传者提供，不是平台自动证明的画面真实性认证。
- “隔离运行预览”使用独立、无同源权限的 allow-scripts 沙箱，模板不能读取父页面登录状态；CSP 禁止外部网络、子页面、插件、表单、弹窗与顶层导航。预览会转换包内 HTML/CSS/JS 相对资源路径，支持本地脚本与固定路径模块依赖；不支持所有动态打包器路径和任意嵌套网页。缺资源或外部依赖会明确报错，不从公网补取。
- 看板只展示模板自身数据，没有 MES/WMS 连接、场景接入、组合大屏编辑或组合 HTML 导出。原有 GLB 场景管理保持独立。

## 从项目版迁移

首次运行新版自动迁移数据库至 v2：保留账号、会话、模型 ID、版本 ID、文件和历史版本；删除项目及成员关系，原模型进入各库“未分类”。原管理员保持管理员；原来任一项目负责人/编辑者成为全库编辑者；其余为查看者。所有成员将可浏览全部库，不再保留旧项目隔离边界。

迁移前必须停服并完整备份数据目录。本次开发前的数据副本在 `backups/data-before-library-v2-20261117/`，不要将备份对外公开。v2 数据库不能直接交给旧服务运行；回滚需停服并恢复完整备份和旧应用。

## 数据备份

默认 `data/` 保存 SQLite 数据库、会话、幂等回执、模型文件、缩略图及 dashboards/ 看板内容。部署路径由 `DATA_DIR` 决定。采用单进程运行，不要将 SQLite 数据目录放到网络共享盘。

安全备份：停止服务后完整复制数据目录（包括数据库及可能的 `-wal` / `-shm`、files/ 和 dashboards/），再启动。恢复时停止服务并恢复整个目录，确保服务账号可读写。不能只备份数据库或只备份原始文件。

不要将 data/ 作为公开静态目录。数据库包含账号信息与会话数据，备份应受访问保护。
